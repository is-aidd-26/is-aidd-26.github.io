## Цели

**Основная цель**: разработать спецификацию и спроектировать API бэкенда.

**Дополнительная цель**: добавить простейший фронтенд и бэкенд с одной функцией: отправка сообщения без сохранения.

## Задания

Обязательные:

- Выбрать вариант проекта
- Написать PRD (Product Research Document) в формате markdown
- Спроектировать API и описать в формате OpenAPI v3
- Добавить фронтенд на TypeScript / React с одной формой отправки сообщения

Необязательные:

- Добавить бэкенд на C# / AST.NET с одним методом API для отправки сообщения, без сохранения

## Требования

### Требования к спецификации

>Из этих требований можно составить хороший промпт — это ваша задача.

1. Написана либо полностью вычитана студентом
2. Описаны все функциональные требования
3. Легко читается человеком
4. Проверена LLM по следующим аспектам:
    - полнота спецификации: нет «слепых пятен», нет упущенной функциональности, необходимой для других возможностей продукта
    - нет противоречий внутри документа
    - нет логических, фактических, грамматических, стилевых ошибок в тексте
    - нет ошибок форматирования markdown
    - достижимость: проект может быть реализован студентом за три месяца параллельно с другими курсами

### Требования к описанию API

>Из этих требований можно составить хороший промпт — это ваша задача.

1. API описан в YAML-файле в формате OpenAPI v3
2. Нет противоречий между OpenAPI схемой и спецификацией
3. Есть описание успешных ответов и ошибок
4. Для каждого свойства в каждой схеме объекта есть пример (`example:`)

### Требования к фронтенду

1. Есть только форма отправки сообщения в чат и ничего лишнего
    - «недоделок» в UI не должно быть
2. В README.md описано как собрать и запустить фронтенд
3. Инструкция по сборке и запуску работает без очевидных проблем у преподавателя на Unix-системе (OSX / Linux)
4. Сборка выполняется без ошибок и предупреждений
5. Если нет бэкенда, то вместо него есть работоспособная заглушка
6. Если есть тесты, то они выполняются без ошибок и предупреждений
    - добавлять тесты в первых лабораторных не требуется

### Требования к бэкенду

>Это необязательная цель — вы можете не делать бэкенд в 1-й лабораторной.

1. Есть только метод отправки сообщения и он только пишет принятое сообщение в логе
    - «недоделок» в API не должно быть
    - базы данных не должно быть
2. В README.md описано как собрать и запустить бэкенд
3. Инструкция по сборке и запуску работает без очевидных проблем у преподавателя на Unix-системе (OSX / Linux)
4. Сборка выполняется без ошибок и предупреждений
5. Если есть тесты, то они выполняются без ошибок и предупреждений
    - добавлять тесты в первых лабораторных не требуется
