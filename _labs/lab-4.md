# Лабораторная 4: Автоматизация качества и TDD

## Цели

**Основная цель:** внедрить в проект обязательное требование по написанию тестов, покрыть критические пути пользователя автотестами. Настроить автоматические проверки кода, запускаемые перед коммитом. Реализовать фичу по TDD.

**Дополнительная цель:** настроить требование по code coverage. Настроить требование по соответствию требований из SDD тестам в проекте.

## Задания

Обязательные:

1. Провести ИИ-ревью собственного кода на соответствие стандартам производительности и безопасности, исправить найденные дефекты
2. Изучить подходящие для вашего языка инструменты проверки кода по стилю, соответствию типов и т.п. (для Python: ruff, flake8 и другие)
3. Настроить локальные автоматические проверки кода на соответствие требованиям (pre-commit)
4. Внедрить обязательное написание тестов при разработке кода: юнит, интеграционные, e2e
5. Настроить необходимое окружение для запуска тестов локально или в контейнере
6. Реализовать хотя бы одну фичу по TDD (RED-GREEN)

Необязательные:

1. Настроить обязательные требования по code coverage (процент покрытия строк/ветвей кода тестами)
2. Настроить требования по соответствию требований из SDD тестам. Например: каждое требование должно иметь тест; каждый тест должен относиться к какому-нибудь требованию

## Требования

### Требования к тестам

1. Тесты разделены по уровню тестирования
2. Тесты разделены по тестируемым частям приложения
3. Тесты отражают реальные бизнес-требования

### Требования к CI

1. Проверки запускаются локально
2. Провальные проверки блокируют коммит в репозиторий
